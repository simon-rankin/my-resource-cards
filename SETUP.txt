# SETUP INSTRUCTIONS

Download these 4 files:
1. package.json
2. build.js  
3. style.css
4. links.md

Then create this folder structure:

```
my-resource-cards/
├── package.json
├── build.js
├── links.md
└── src/
    └── style.css
```

## Steps:

1. Create a folder called `my-resource-cards`
2. Put `package.json`, `build.js`, and `links.md` in the main folder
3. Create a subfolder called `src`
4. Put `style.css` inside the `src` folder

5. Open terminal in `my-resource-cards` folder and run:
   ```
   npm install
   npm run build
   ```

Done! Your site will be in the `dist` folder.

## To deploy to GitHub:

1. Create new repo on GitHub
2. In your `my-resource-cards` folder:
   ```
   git init
   git add .
   git commit -m "Initial commit"
   git remote add origin https://github.com/YOUR-USERNAME/YOUR-REPO.git
   git push -u origin main
   ```

3. Enable GitHub Pages in repo settings (use gh-pages branch)

That's it!

## Rebuilding after adding links

`npm run build` only scrapes links it hasn't seen before. Everything else is
reused from scrape-cache.json, so adding a link or a new section takes seconds.
Commit scrape-cache.json along with dist/.

To re-scrape (e.g. to pick up a site's new thumbnail):

   npm run refresh                          # every link (~10 minutes)
   npm run refresh -- "Alumni Websites"     # one section, by heading or page slug

If a site can't be reached during a refresh, its card keeps the previous version.
To re-scrape a single link, delete its entry from scrape-cache.json and build.

## Student video galleries (Animated Album Covers)

Defined in videos.md with two option lines and no video entries:

   # Animated Album Covers
   playback: click
   source: apple-music-animated-albumcovers

Drop the student .mp4s into that folder (filenames can include names and IDs -
the folder is gitignored and never published), then:

   npm run encode -- "Animated Album Covers"
   npm run build

Clips are published as animated-album-covers-01.mp4, -02, ... with names and
embedded metadata stripped and sound kept. The numbering is a fixed shuffle,
not alphabetical, so numbers can't be matched to a class list. Adding or
removing files renumbers them.
